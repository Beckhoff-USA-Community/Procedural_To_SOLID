    Reference¶

    Quick-lookup material for instructors and students working in the repo.

    Repo layout¶

    NEM2026/
├── NEM2026.sln                    # VS solution — open this in XAE
├── NEM2026.tspproj                # TwinCAT System project (refs FillingLine.plcproj)
├── _Boot/                         # build output — regenerated by XAE
│   └── TargetDescription.xml      # target version pin
└── FillingLine/                   # PLC project (renamed from Machine3Ways)
    ├── FillingLine.plcproj        # library refs vary per stage branch (see below)
    ├── PlcTask.TcTTO              # task: 10 ms cycle, priority 20, calls MAIN
    ├── POUs/                      # programs, FBs, methods (Structured Text in XML)
    │   ├── Interfaces/            # (Stage 3 only) — SOLID contracts
    │   ├── BuildingBlocks/        # (Stage 3 only) — composable primitives
    │   ├── Stations/              # (Stage 3 only) — composed station FBs
    │   ├── FB_Station*.TcPOU      # (Stages 1+2) — flat station FBs at this level
    │   ├── FB_StationBase.TcPOU   # (Stage 2 only) — abstract base
    │   └── MAIN.TcPOU             # cyclic entry point
    ├── DUTs/                      # struct types (ST_LogEntry on Stage 3)
    ├── GVLs/                      # global variable lists (currently empty)
    ├── VISUs/                     # TwinCAT HMI visualizations (currently empty)
    └── _Libraries/                # resolved library cache (committed for offline use)

    The _Libraries/ directory is committed deliberately. It contains pre-resolved copies of every library any stage references (Core, SPT, Mc3, XTS, Tc2, Tc3) so XAE can resolve placeholder references offline during the workshop without a NuGet feed. Don't delete entries from _Libraries/ even when pruning placeholder references on a particular branch.

    Library policy per stage¶

    Each stage branch carries only the placeholder references it actually needs. This keeps the project tree clean and makes the framework distinction visible at the project-properties level.

    Branch family Required <PlaceholderReference> entries
    main, stage-1-* Tc2_Standard, Tc2_System, Tc3_Module
    stage-2-* above + SPT Base Types, SPT Components, SPT Diagnostic, SPT Event Logger, SPT Utilities, Tc3_EventLogger, Tc3_PackML_V3
    stage-3-* above-base + Core, CoreComponents, Tc3_EventLogger

    The actual library files are present on disk in _Libraries/ regardless of which branch you're on — only the plcproj references differ.

    TwinCAT XML envelope¶

    Every .TcPOU, .TcDUT, .TcGVL, .TcIO file follows this shape:

    <?xml version="1.0" encoding="utf-8"?>
<TcPlcObject Version="1.1.0.1">
  <POU Name="FB_Whatever" Id="{guid-here}" SpecialFunc="None">
    <Declaration><![CDATA[FUNCTION_BLOCK FB_Whatever
VAR_INPUT
    ...
END_VAR
]]></Declaration>
    <Implementation>
      <ST><![CDATA[
        // body code
      ]]></ST>
    </Implementation>
    <Method Name="MyMethod" Id="{another-guid}">
      <Declaration><![CDATA[METHOD MyMethod : BOOL
VAR_INPUT
    ...
END_VAR
]]></Declaration>
      <Implementation>
        <ST><![CDATA[
          // method body
        ]]></ST>
      </Implementation>
    </Method>
    <Property Name="MyProp" Id="{guid}">
      <Declaration><![CDATA[PROPERTY MyProp : BOOL
]]></Declaration>
      <Get Name="Get" Id="{guid}">
        <Declaration><![CDATA[]]></Declaration>
        <Implementation>
          <ST><![CDATA[MyProp := SomeVar;]]></ST>
        </Implementation>
      </Get>
    </Property>
  </POU>
</TcPlcObject>

    For interfaces, use <Itf> instead of <POU>, and method/property <Get> blocks have only <Declaration> — no <Implementation>.

    Editing conventions¶

    If you're contributing back, follow these:

    • Type prefixes (FB_, I_, ST_, E_) on type names. No Hungarian on instance variables (no b, r, n, s prefixes). Internal private vars use a leading underscore (_Mode, _Latched).
    • GUIDs are stable identities. Don't regenerate them when editing existing files. Generate new ones for new objects with uuidgen.
    • Property attributes for HMI binding: {attribute 'monitoring' := 'call'} on read-only properties that the HMI should display live.
    • Internal vars hidden from automatic HMI symbolization: {attribute 'hide'} directly above the declaration.

    Stage 1 drift is deliberate¶

    Don't tidy these up — they're pedagogical:

    • Alarm-ack inconsistency (R_TRIG in Fill/Label, level in Cap/Inspect)
    • Step numbering 0/100/200/300 in FB_StationLabel
    • Dead ManualStep variable in FB_StationInspect

    If you "fix" them, the CR-1 reveal moment ("how many of you copied from Fill?") loses its punch.

    Compiler warnings¶

    Disabled project-wide on every branch:

    Warning ID What it complains about Why we silence it
    410 "no string lengths specified for STRING types" Stage 1's CASE machines use bare STRING for transient strings; not worth the noise
    5410 "non-deterministic struct initialization" Comes up with extended FB_Init patterns

    These are configured in FillingLine.plcproj under DisabledWarningIds.
